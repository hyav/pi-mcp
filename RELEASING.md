# Releasing `@hyav/pi-mcp`

This repository publishes from a reviewed jj revision. A `v*` tag triggers `.github/workflows/publish.yml`, which verifies the tag, publishes the npm package with npm Trusted Publishing/OIDC, and creates the matching GitHub Release.

`RELEASING.md` is a maintainer runbook and is intentionally excluded from the npm artifact.

## First npm publication

Trusted Publisher settings are attached to an existing npm package. Because `@hyav/pi-mcp` has not been published yet, publish `0.1.0` once from the final release revision with an npm account protected by 2FA:

```sh
npm publish --access public
```

Run `npm publish --dry-run --access public` first if the artifact still needs inspection. Do not add `--provenance` to this local publish; npm provenance is generated by the later GitHub-hosted OIDC workflow.

After the package exists, open its npm Settings → Trusted publishing and add a GitHub Actions publisher with:

- Organization or user: `hyav`
- Repository: `pi-mcp`
- Workflow filename: `publish.yml`
- Environment name: empty unless a protected GitHub environment is introduced
- Allowed action: `npm publish`

The GitHub repository and `package.json.repository.url` must match exactly. Configure this separately for each `@hyav` package.

Then push the reviewed `v0.1.0` tag. The workflow checks that npm already contains this exact release commit and skips a duplicate npm publish while still creating the GitHub Release. Future tags publish through OIDC.

## Later releases

1. Update `package.json` and `CHANGELOG.md` together.
2. Run the repository quality gate and inspect the real npm artifact.
3. Record the final jj revision and create `v<version>` on that exact revision.
4. Push the reviewed commit and tag through the configured GitHub remote.
5. Confirm the `publish` job receives `id-token: write` and publishes without `NPM_TOKEN`.
6. Verify the npm provenance record and the GitHub Release assets.

Do not reuse a published version or move a published tag. If npm publication succeeds but GitHub Release creation fails, rerun the failed `release` job after checking the uploaded assets; do not publish the same npm version again.

## Lock down after bootstrap

After the first successful OIDC publication, remove unused npm automation tokens and enable “Require two-factor authentication and disallow tokens” in npm package publishing access. Protect the `main` branch and `v*` release tags in GitHub.

References: [npm Trusted Publishing](https://docs.npmjs.com/trusted-publishers/), [npm provenance](https://docs.npmjs.com/generating-provenance-statements/), and [staged publishing](https://docs.npmjs.com/staged-publishing/).
